# Audit aplikasi TOEFL — 20 September 2026

**Kesimpulan: belum layak dipakai untuk ujian berisiko tinggi atau penerbitan hasil yang dipercaya tanpa perbaikan kontrol sesi, integritas jawaban, waktu, dan sertifikat.** Fondasi Laravel, relasi database, dan React sudah ada, tetapi keberhasilan build belum menjamin kebenaran proses ujian.

### Eksekusi perbaikan tahap produksi — 20 September 2026

Perubahan tahap ini telah diterapkan ke workspace dan database lokal: audit event untuk aksi ujian/admin, snapshot paket dan kunci saat attempt dimulai, versi scoring pada hasil, command terjadwal untuk menandai sesi kedaluwarsa, timezone jadwal yang tersimpan secara eksplisit, validasi import paket tiga section, ekspor CSV bertahap, batas ukuran import, indeks deadline/status, serta semantik aksesibilitas untuk pilihan jawaban dan modal ujian. Migration forward `2026_09_20_000004_backfill_package_snapshot` juga menutup database lama yang sebelumnya sudah menandai migration hardening sebagai selesai tetapi belum memiliki kolom snapshot. Verifikasi akhir: 15 test lulus dengan 38 assertion, PHPStan level 7 lulus tanpa error, Pint lulus, build Vite produksi lulus, dan UAT HTTP menjalankan alur demo, autentikasi, dashboard, logout, serta ujian token tiga section.

### Status remediation

Perubahan pada workspace ini telah menutup sebagian besar jalur P0 yang dapat diperbaiki langsung: pemeriksaan kepemilikan sesi dan binding token ke session browser, deadline section di server, patch jawaban tanpa menghapus pilihan, token sekali pakai dengan entropy lebih tinggi, pencegahan akses paket langsung, validasi soal terhadap paket/section, sanitasi payload sertifikat publik, status sertifikat dicabut, private payment proof, pembatasan upload, throttle login, bounded admin sessions, filter ekspor jadwal, pencegahan perubahan paket saat attempt aktif, pengacakan demo, dan lazy loading halaman React. Start attempt juga dibuat atomik dengan lock registrasi; transisi section yang terlambat tidak mengembalikan waktu yang sudah lewat. Probe regresi terisolasi diperbarui untuk menegakkan perilaku aman.

Masih perlu pekerjaan lanjutan sebelum sign-off produksi: concurrency/load test MySQL, migrasi pada database nyata, pagination semua daftar admin, streaming ekspor besar, audit trail/retensi, deployment hardening, QR code, dan uji browser/aksesibilitas visual. Dependency yang semula terdeteksi advisory telah diperbarui dan `composer audit --locked` sekarang bersih. Temuan di bawah tetap dipertahankan sebagai baseline audit; status implementasi tidak menghapus kebutuhan verifikasi penerimaan.

Audit ini mencakup kode backend/frontend, routes, skema dan agregat MySQL lokal, autentikasi, penyimpanan jawaban, scoring, pembayaran, impor/ekspor, dependency, serta tinjauan layout dan aksesibilitas dari kode. Ditambahkan pengujian audit terisolasi dan skrip inventaris baca-saja; build memperbarui artefak `public/build`.

## Temuan prioritas

### A01 — P0 — Sesi ujian tidak memiliki pemeriksaan pemilik — uji

Sumber: `app/Http/Controllers/ToeflApiController.php:168`, `:181`, `:190`, `:202`, `:210`, `:230`; `routes/api.php:8`.

Endpoint membaca soal, menjawab, pindah section, menambah pelanggaran, submit, dan membaca hasil hanya mencari ID sesi. Middleware `web` menyediakan session/CSRF, tetapi tidak membuktikan hak atas sesi ujian. Tamu yang mengetahui ID dapat membaca dan mengubah sesi. UUID mengurangi peluang menebak, tetapi tidak menggantikan otorisasi. Pengujian tamu berhasil membaca sesi, menyimpan jawaban, dan menyelesaikannya.

Perbaikan: policy kepemilikan untuk peserta login; sesi token harus terikat ke session browser atau kredensial akses khusus yang diverifikasi server. Pisahkan izin admin/proktor dan terapkan pemeriksaan pada semua endpoint, bukan hanya halaman React. Kriteria lulus: pengguna B dan tamu ditolak untuk seluruh aksi sesi A; akses token tidak bergantung pada URL saja.

### A02 — P0 — Jawaban dari paket/section lain diterima dan dihitung — uji

Sumber: `ToeflApiController.php:181`, `:210`.

`answer()` tidak memeriksa bahwa soal milik paket sesi dan section yang sedang aktif. `submit()` menghitung semua relasi jawaban yang disimpan. Probe berhasil memasukkan soal paket lain dan mendapatkan tambahan listeningRaw. Peserta juga dapat mengubah section lama melalui API meskipun UI menyatakan sudah terkunci.

Perbaikan: validasi question melalui paket, section aktif, status, dan deadline sesi; batasi nilai A–D/null. Scoring harus menghitung hanya snapshot soal sah untuk attempt tersebut. Kriteria lulus: soal lintas paket, section lama/masa depan, dan nilai tidak sah ditolak.

### A03 — P0 — Timer dapat direset dan tidak diberlakukan server — kode + uji sesi lama

Sumber: `resources/js/lib/examStore.js:23`, `:54`; `resources/js/Pages/Exam.tsx:126`; skema `exam_sessions`; `ToeflApiController.php:181`.

Waktu berkurang lewat interval browser dan tersimpan dalam localStorage. Server tidak menyimpan deadline section atau menolak jawaban terlambat. Menghapus state lokal memberi durasi baru; menutup browser menghentikan pengurangan; throttling tab dapat menyebabkan drift. Probe sesi yang dimulai dua hari lalu masih menerima jawaban dan submit. `Student/Dashboard.tsx:321` juga memanggil resetExam setelah start/resume, sehingga jalur melanjutkan sesi dapat mengembalikan durasi penuh.

Perbaikan: simpan section_started_at, section_deadline_at dan status transisi server; kirim serverNow/deadline; UI menghitung selisih waktu. Deadline tetap berlaku ketika offline, refresh, atau browser ditutup. Tambahkan proses server untuk mengakhiri sesi kedaluwarsa dengan aturan pemulihan yang jelas.

### A04 — P0 — Mark for review menghapus jawaban — uji

Sumber: `ToeflApiController.php:186`; `Exam.tsx:309`.

Frontend mengirim hanya isMarkedForReview; backend mengisi selected_answer dengan null saat field tersebut tidak ada. Sebaliknya menyimpan pilihan mereset review menjadi false. Tampilan lokal masih dapat memperlihatkan jawaban yang sudah hilang di database.

Perbaikan: gunakan semantik patch, ubah hanya field yang dikirim. Kriteria lulus: tandai/batalkan review tidak mengubah pilihan; mengganti pilihan tidak mengubah review tanpa instruksi.

### A05 — P1 — Akses paket dan waktu terjadwal dapat dilewati — uji

Sumber: `ToeflApiController.php:143`.

Peserta login dapat meminta start menggunakan packageId tanpa pendaftaran/pembayaran. Tidak ada validasi operating mode pada jalur itu. Request peserta juga menerima bypassTime=true untuk melewati pemeriksaan waktu mulai. Probe jadwal dua hari di masa depan menghasilkan 403 tanpa flag dan 200 dengan flag.

Perbaikan: validasi entitlement server untuk mode komersial/institusi dan paket gratis; override waktu hanya izin proktor yang diaudit. Pemeriksaan jadwal aktif, paket aktif, batas akhir, dan status pembayaran harus berlaku juga pada resume.

### A06 — P1 — Token dapat dipakai berulang tanpa batas penggunaan — uji

Sumber: `ToeflApiController.php:69`; `AdminApiController.php:129`; `app/Models/ExamToken.php`.

is_used tidak diperiksa/diperbarui; token yang ditandai sudah digunakan tetap membuat beberapa sesi. Token otomatis hanya empat digit setelah prefix tetap, dan tidak ada throttle aplikasi. Jika token memang untuk kelas, diperlukan kapasitas/masa berlaku, bukan asumsi sekali pakai. Token tanpa paket juga memilih paket aktif terbaru secara implisit.

Perbaikan: definisikan token individu/kelas, expiry, kuota pemakaian atomik, pengikatan identitas, revocation, dan batas percobaan.

### A07 — P1 — Autosave/offline dapat kehilangan atau menimpa jawaban — kode

Sumber: `Exam.tsx:232`, `:264`, `:309`, `:337`, `:367`.

Antrean offline dihapus setelah fetch tanpa memeriksa res.ok. HTTP 419/422/500 dapat dianggap sukses. Replay hanya dipicu event online, bukan saat startup atau pemulihan kesalahan server ketika koneksi tetap online. Request pilihan cepat tidak memiliki revisi sehingga respons/penyimpanan lama berpotensi menimpa pilihan baru. Transisi dan submit tidak menunggu semua save/replay selesai. Review juga tidak memeriksa status HTTP.

Perbaikan: antrean persisten per sesi/soal dengan revision, acknowledgment server, retry terbatas dan backoff; flush sebelum transisi/submit; tampilkan status menyimpan/tersimpan/gagal. Uji koneksi putus, 419/500, refresh, klik cepat, request terlambat, dan submit saat pending.

### A08 — P1 — Upload audio mempertahankan ekstensi bebas di direktori publik — kode

Sumber: `AdminApiController.php:246`.

Endpoint admin menerima file apa pun, memakai ekstensi asli, dan memindahkannya ke public/uploads/audio. Jika web server mengeksekusi PHP di direktori itu, akun admin yang disalahgunakan dapat mengunggah file executable. Eksekusi server tidak diuji. Tidak ada batas ukuran/MIME di aplikasi.

Perbaikan: allowlist MIME/format audio dan ukuran; nama/ekstensi ditentukan server; direktori upload tidak boleh mengeksekusi script; gunakan storage terkontrol. Jangan menganggap batas PHP sebagai validasi aplikasi.

### A09 — P1 — Data pribadi ikut terbuka pada verifikasi sertifikat — uji

Sumber: `ToeflApiController.php:269`; `app/Models/User.php`.

Endpoint publik mengembalikan toArray seluruh certificate beserta user dan session.registration.schedule. Password memang disembunyikan, tetapi email, nomor telepon, nomor identitas, dan detail registrasi/pembayaran dapat ikut terpapar. Probe mengonfirmasi email dan telepon user muncul pada request tamu.

Perbaikan: response resource publik dengan allowlist minimal seperti nama, nomor sertifikat, tanggal, hasil, dan status validitas. Endpoint dokumen lengkap harus memiliki izin berbeda. URL/kode verifikasi publik tidak boleh menjadi izin membaca profil peserta.

### A10 — P1 — Sertifikat revoked tetap diberi tampilan valid — kode

Sumber: `resources/js/Pages/Verify.tsx:33`, `:142`; `resources/js/Pages/Certificate.tsx`; `ToeflApiController.php:269`.

Model memiliki is_revoked tetapi halaman Verify selalu menampilkan “Sertifikat Resmi Terverifikasi” setelah response berhasil; flag tidak menjadi kondisi tampilan. Endpoint cetak juga mengembalikan dokumen. Database lokal belum memiliki sertifikat revoked, sehingga ini jalur cacat yang belum terjadi pada sampel data tersebut. qrDataUrl selalu null, sehingga QR tidak muncul meskipun tampilan menyiapkan tempatnya.

Perbaikan: status valid/revoked yang eksplisit di API dan UI; tampilkan dokumen dibatalkan dengan jelas; terbitkan QR yang menuju URL verifikasi, serta uji cetak dan scan.

### A11 — P1 — Race condition pada kuota, attempt, hasil, dan nomor sertifikat — risiko kode

Sumber: `ToeflApiController.php:110`, `:143`, `:210`; `app/Support/CertificateService.php:12`; migration `exam_registrations`.

Pemeriksaan kuota dan insert terpisah; belum ada unique(schedule_id,user_id). Dua request dapat melampaui kuota/menggandakan pendaftaran. Start sesi dan update registrasi tidak atomik. Submit memeriksa hasil sebelum transaksi tanpa lock; unique session_id mencegah hasil ganda tetapi request bersaing dapat berakhir error. Nomor sertifikat memakai count()+1 sehingga dua penerbitan berbeda dapat memilih nomor sama; sertifikat dibuat setelah transaksi hasil selesai. GET result juga bisa menerbitkan sertifikat.

Perbaikan: transaksi dengan lock pada record yang tepat, constraint unik, idempotency key, sequence nomor atomik, retry konflik, dan transisi status konsisten. Uji paralel di MySQL diperlukan; probe audit ini tidak mengklaim telah mereproduksi race.

### A12 — P1 — Status pembayaran dan penghapusan jadwal tidak melindungi riwayat — kode

Sumber: `ToeflApiController.php:127`; `AdminApiController.php:141`, `:175`; migration foreign key exam_registrations.

Unggah bukti pembayaran dapat menurunkan status registrasi yang sudah confirmed/completed ke waiting approval. Admin approve/reject tidak membatasi status asal. Delete jadwal melakukan hard delete dan cascade registrasi, termasuk riwayat pembayaran. Batas pendaftaran tidak diperiksa saat enroll; status batal/ditolak tetap dihitung terhadap kuota.

Perbaikan: definisikan tabel transisi status, lindungi tiket selesai, gunakan pembatalan/arsip jadwal, simpan audit perubahan dan kebijakan refund/retensi. Bukti pembayaran saat ini berada di URL publik dan hanya divalidasi berdasarkan ekstensi; pindahkan ke private storage dengan akses peserta/verifikator.

### A13 — P1 — Tidak ada throttle autentikasi dan endpoint pembuatan sesi — kode

Sumber: `routes/api.php`; `bootstrap/app.php`; `ToeflApiController.php:33`, `:51`; `AdminApiController.php:40`.

Login peserta/admin, registrasi, token, dan demo tidak memakai pembatas percobaan pada konfigurasi aplikasi yang ditinjau. Registrasi menerima password enam karakter dan tidak menggunakan Password::defaults produksi yang sudah didefinisikan. Batas panjang field dan validasi terpusat tidak konsisten. Perlindungan reverse proxy produksi belum diperiksa.

Perbaikan: FormRequest, throttle berbasis IP+identitas dengan respons umum, aturan password yang benar-benar dipakai, serta pemulihan akun sesuai kebutuhan. Sentralisasikan guard/policy admin; role verifikator, penyusun soal dan proktor belum dipisahkan.

### A14 — P1 — Kunci demo tersedia sebelum selesai — uji

Sumber: `ToeflApiController.php:261`; `resources/js/Pages/Demo.tsx:189`; `app/Support/DemoQuestionService.php:9`, `:23`.

GET demo/result mengembalikan correctAnswer dan pembahasan saat status IN_PROGRESS. Frontend demo sendiri memanggil endpoint ini. Submit dapat mengubah ulang hasil demo yang telah selesai, dan akses tidak terikat pemilik. Fungsi shuffle memilih original dan key dari array yang sama sehingga tidak benar-benar memindahkan opsi ke huruf berbeda.

Perbaikan: endpoint resume tersanitasi, pembahasan hanya setelah selesai, otorisasi sesi demo, submission final idempotent; remap opsi ke urutan A–D baru jika pengacakan memang diperlukan. Tetapkan apakah demo boleh diulang dan bagaimana statistik lead dihitung.

### A15 — P1 — Label CEFR dan klaim skor resmi terlalu kuat — uji + referensi ETS

Sumber: `app/Support/ToeflScoring.php:43`; `Exam.tsx:1071`.

Jawaban kosong menghasilkan skor 310 tetapi diberi A2; tidak ada kondisi di bawah ambang A2. ETS menyebut ambang A2 337 pada studi pemetaan, dan menyediakan descriptor per section. Tabel raw-to-scaled dikodekan tetap; asal dan kalibrasi per bentuk tes tidak terdokumentasi, sedangkan tabel database score_conversions tidak dipakai oleh service ini. Modal submit menyatakan seluruh 140 soal sudah diselesaikan dan memakai “official ETS scale”, meskipun jawaban boleh kosong dan paket dapat tidak lengkap.

Perbaikan: label skor perkiraan untuk simulasi, dokumentasikan sumber/version scoring, tangani below-A2, gunakan jumlah jawaban aktual, dan verifikasi pemetaan terhadap paket yang disahkan. Kesamaan rentang skor tidak membuktikan validitas psikometrik atau status resmi.

Referensi: [ETS scoring](https://www.ets.org/toefl/itp/scoring.html), [ETS pemetaan CEFR](https://www.ets.org/Media/Research/pdf/RM-11-33.pdf), [descriptor Level 1](https://www.ets.org/pdfs/toefl/toefl-itp-level-1-score-descriptors.pdf).

**N+1:** penggunaan with/withCount pada daftar sesi, jadwal, paket, dan ekspor sudah baik. Probe daftar sesi menghasilkan jumlah query konstan. `submit()` juga eager-load answers.question.section. ## Layout, UI/UX, dan kesesuaian format tes

Implementasi paling dekat dengan **simulasi TOEFL ITP Level 1**: Listening 50 soal/35 menit, Structure 40/25 menit, Reading 50/55 menit. Data lokal dan durasi section sesuai pola itu. TOEFL iBT memiliki empat keterampilan dan format berbeda; implementasi ini tidak boleh dinilai sebagai implementasi iBT lengkap. [ETS ITP content](https://www.ets.org/toefl/itp/test-content.html), [ETS iBT content](https://www.ets.org/toefl/test-takers/ibt/about/content.html).

Sudah tersedia sound check, timer yang dapat disembunyikan, pemisahan bacaan/soal, navigasi nomor, penandaan review, dialog akhir section, dan pembatasan mundur Listening pada UI. Namun ada masalah berikut:

## Dependency dan operasional

Baseline Composer audit menemukan advisory pada Guzzle, league/commonmark, dan Livewire. Dependensi terkait sudah diperbarui dan verifikasi `composer audit --locked` pada lockfile sekarang menghasilkan 0 advisory dan 0 abandoned package. Batas versi Inertia dan PhpSpreadsheet juga sudah dipersempit ke rentang terkontrol. Dependensi Livewire/Blaze berasal dari starter kit dan tetap perlu ditinjau apakah masih dibutuhkan oleh aplikasi React.

Konfigurasi yang diamati adalah **lokal**, bukan bukti salah konfigurasi produksi: APP_ENV=local, debug=true, timezone UTC, session/cache/queue database, cookie secure tidak ditetapkan eksplisit, PHP 128M. Pada produksi perlu verifikasi HTTPS, cookie aman, debug mati, document root public, pembatasan upload, PHP worker/OPcache, log tanpa data sensitif, dan backup terenkripsi yang pernah diuji restore. Tidak ada job pemantauan/expiry ujian pada routes/console.php; queue database saja belum berarti workflow asinkron tersedia.

Belum terlihat audit trail terstruktur untuk perubahan kunci, pembayaran, override waktu, revoke sertifikat, atau penghapusan jadwal. Perlindungan privasi memerlukan kebijakan retensi demo lead, bukti transfer, jawaban dan sertifikat, serta minimisasi data pada endpoint publik. Penilaian hukum/izin materi membutuhkan dokumen organisasi dan berada di luar bukti teknis audit ini.

## Urutan perbaikan dan syarat penerimaan

1. **Integritas ujian:** A01–A04, A07. Otorisasi semua endpoint, validasi soal, timer server, patch jawaban, dan save acknowledgment. Semua kasus lintas user/section serta offline harus memiliki regression test.
2. **Akses dan dokumen:** A05–A15. Tutup bypass, batasi token/upload/login, kecilkan payload publik, benar-benar tampilkan revoke, benahi transaksi/sertifikat dan status pembayaran.
3. **Kebenaran konten dan workflow:** A24–A25, A29–A34. Blueprint paket, snapshot, impor/ekspor, waktu lintas zona dan scoring terverifikasi.
4. **Skalabilitas:** A16–A23. Pagination, aggregate SQL, streaming ekspor, lazy loading, state persisten minimum. Ukur dengan skenario peserta serentak yang disepakati; tetapkan sasaran p95 save/submit dan batas error berdasarkan infrastruktur.
5. **Validasi sebelum rilis:** uji end-to-end Listening → Structure → Reading → hasil → sertifikat; refresh/resume, jaringan putus, submit berulang, role berbeda, jadwal penuh, pembayaran ditolak, audio gagal, revoke, keyboard/zoom, cetak dan scan QR. Jalankan load test dan soak test durasi ujian penuh di staging MySQL, bukan terhadap peserta nyata.

Untuk mengulang bukti: `php artisan test tests/Audit/CurrentBehaviorAuditTest.php`. File probe berada di luar suite default agar tidak membuat perilaku rentan dianggap regression requirement. Setelah perbaikan, ubah menjadi assertions untuk perilaku aman dan masukkan kasus relevan ke suite normal. Inventaris agregat: `php docs/audit/read-only-inventory.php`.
